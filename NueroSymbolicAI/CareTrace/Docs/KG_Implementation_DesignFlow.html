Design principles (why this shape)

  • SNOMED SCTIDs are used as stable node identifiers; labels are resolved from Snowstorm.
  • The graph stays small and inspectable: seed concepts are curated for the scenarios, then expanded with strict caps.
  • Relationships separate hierarchy (IS_A) from attributes (REL with typeId/typeTerm).
  • Scenarios are represented explicitly with Patient nodes so the KG supports narrative grounding and example queries.

Relationship types created

  • Concept ↔ Concept
    • IS_A — hierarchy edges (parent concepts)
    • REL — non-ISA attribute edges (stored with typeId, typeTerm)
  • Patient → Concept
    • HAS_SYMPTOM, HAS_FINDING, HAS_DIAGNOSIS, ON_MEDICATION, HAS_PROCEDURE

LLM usage

No LLM is used to construct this knowledge graph. Concept IDs are manually selected for scope, preferred terms are resolved via Snowstorm, and expansion/loading is deterministic.

Validation query (counts)

MATCH (c:Concept)  WITH count(c)  AS concept_nodes
MATCH (p:Patient)  WITH concept_nodes, count(p) AS patient_nodes
MATCH ()-[r:IS_A]->() WITH concept_nodes, patient_nodes, count(r) AS isa_edges
MATCH ()-[r:REL]->()  RETURN concept_nodes, patient_nodes, isa_edges, count(r) AS rel_edges
